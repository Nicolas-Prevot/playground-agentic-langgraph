# Release notes workflow

1. State the user-visible outcome before implementation detail.
2. Separate additions, changes, and fixes only when each section has content.
3. Mention migration or compatibility impact explicitly.
4. Do not claim validation that was not performed.
5. Check the result against [the checklist](references/CHECKLIST.md).
